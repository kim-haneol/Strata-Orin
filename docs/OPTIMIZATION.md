# Strata Gyro-M Porting and Inference Optimization Record for Jetson AGX Orin 64GB

## 1. Purpose, Experimental Timeline, and Scope

This document is a technical reference recording the ARM64 and SM87 porting and kernel/runtime optimization process conducted to run the `Qwen3.8-Flash-Next-Gyro-M` model (`TQ2_0` / native `TQ2_T` routed experts) on the Jetson AGX Orin 64GB. All experiments and measurements were centered on the intensive optimization work carried out between October 7 and October 9, 2026 ([evidence/strata-gyro-orin-20261007](../orin/evidence/strata-gyro-orin-20261007/README.md) to [evidence/strata-gyro-dense-f16-cache-20261009-v1](../orin/evidence/strata-gyro-dense-f16-cache-20261009-v1/README.md)); subsequent operational updates between October 9 and October 15 involving 262K context expansion, CUDA vision integration, abliterated weight deployment, and delta re-encoding ([evidence/strata-gyro-262k-persistent-20261009-v1](../orin/evidence/strata-gyro-262k-persistent-20261009-v1/README.md), [evidence/gyro-abliterated-vision-deploy-20261011-v1](../orin/evidence/gyro-abliterated-vision-deploy-20261011-v1/README.md), [evidence/gyro-abliterated-update-20261015-v1](../orin/evidence/gyro-abliterated-update-20261015-v1/README.md)) are recorded separately from the initial performance experiments. This document serves as an experimental preservation record accompanying a personal reference fork, with no commitment to ongoing upstream synchronization or general user support.

References to "current" or "now" in past evidence documents denote the configuration adopted at the specific time that each document was authored. This document distinguishes and treats separately four execution configurations that varied across experimental phases without conflating them:

1. **2026-10-07 Initial 16K Smoke Configuration**: A single-run execution at 16,384 context conducted immediately after porting for functional verification ([evidence/strata-gyro-orin-20261007](../orin/evidence/strata-gyro-orin-20261007/README.md)).
2. **2026-10-07–08 32K Fixed-Input Benchmark Configuration**: A configuration evaluating prefill and decode kernels at 32,768 context using identical 2,048- and 25,000-token Korean explanatory prompts and 512 greedy output tokens ([evidence/strata-gyro-mtp-20261007-v1](../orin/evidence/strata-gyro-mtp-20261007-v1/README.md) to [evidence/strata-gyro-sub8-ab-20261008-v1](../orin/evidence/strata-gyro-sub8-ab-20261008-v1/README.md)).
3. **2026-10-08–09 64K Hermes Agent Replay Configuration**: A configuration sequentially replaying 61 real agent requests at 65,536 context with prompt checkpoints and conversation caching enabled ([config/strata-gyro-replay-f16cache.json](../orin/config/strata-gyro-replay-f16cache.json), [evidence/hermes-replay-ab-20261008-v1](../orin/evidence/hermes-replay-ab-20261008-v1/README.md) to [evidence/strata-gyro-dense-f16-cache-20261009-v1](../orin/evidence/strata-gyro-dense-f16-cache-20261009-v1/README.md)).
4. **2026-10-09–15 262K Persistent Deployment Configuration**: An operational configuration with context expanded to 262,144, subsequently incorporating vision and abliterated weights ([config/strata-gyro-orin-server.json](../orin/config/strata-gyro-orin-server.json)).

### Summary of Representative Results (Separated by Workload)

- **32K Fixed-Input Benchmark (2,048 / 25,000 input, 512 output)**:
  - Enabling Multi-Token Prediction (MTP) speculative decoding in the resident engine boosted stream decode throughput from 14.60 → 20.35 tok/s (1.394×) on the 2K input and from 14.51 → 19.93 tok/s (1.374×) on the 25K input ([evidence/strata-gyro-mtp-20261007-v1](../orin/evidence/strata-gyro-mtp-20261007-v1/README.md)).
  - Isolating a dedicated prefill buffer (`--no-prefill-borrow`) to prevent prefill from borrowing GPU expert cache slots and expanding the chunk size to 8,192 (`--prefill 8192`) reduced 25K input TTFT (Time To First Token) from 120.033 s → 89.111 s → 47.350 s (2.54× faster compared to the initial borrowed 1,024-chunk configuration) ([evidence/strata-gyro-prefill-borrow-20261007-v1](../orin/evidence/strata-gyro-prefill-borrow-20261007-v1/README.md), [evidence/strata-gyro-prefill-chunk-own-20261007-v2](../orin/evidence/strata-gyro-prefill-chunk-own-20261007-v2/README.md)).
  - Applying shared-memory row and codebook staging (`stage-lut`) to the `TQ2_T` routed-expert kernel, 4-row-per-warp processing with an 8-lane sub-warp down path (`sub8`), and GGML MMQ shared-memory codebook staging (`mmq-lut`) raised 25K internal prefill throughput to 554.91–555.34 tok/s (TTFT 45.10 s) and stream decode to **25.73–25.80 tok/s at 2K and 23.13–23.20 tok/s at 25K** ([evidence/strata-gyro-tq2t-stage-lut-ab-20261007-v1](../orin/evidence/strata-gyro-tq2t-stage-lut-ab-20261007-v1/README.md), [evidence/strata-gyro-mmq-lut-ab-20261007-v1](../orin/evidence/strata-gyro-mmq-lut-ab-20261007-v1/README.md), [evidence/strata-gyro-sub8-ab-20261008-v1](../orin/evidence/strata-gyro-sub8-ab-20261008-v1/README.md)).
- **64K Hermes 61-Request Multi-Turn Replay (21,644 total output tokens, 1,055,326 cached tokens reused)**:
  - Starting from the `sub8` serving build (aggregate decode 26.16 tok/s, total prompt time 271.9 s, total wall time 1,110.0 s), sequentially applying prompt `Q8_0` → FP16 coalesced dequantization and consecutive-turn conversation parking bypass (`dqpark`), checkpoint buffer recycling (`recycle`), English/code/Hangul (`enko`) draft vocabulary reduction, resident expert group gather (`grpres`), and dense FP16 weight caching (`f16cache`) achieved **27.02 tok/s aggregate decode, 211.1 s total prompt time, and 1,026.9 s total wall time** (outputs across all 61 requests identical) ([evidence/strata-gyro-dense-f16-cache-20261009-v1](../orin/evidence/strata-gyro-dense-f16-cache-20261009-v1/README.md), [compare-61.txt](../orin/evidence/strata-gyro-dense-f16-cache-20261009-v1/compare-61.txt)).
  - **Interpretation Caveat**: 27.02 tok/s is the aggregate decode speed across 21,644 tokens generated across 61 Hermes requests under the `f16cache` + `enko` configuration on October 9, 2026. This is not end-to-end throughput, not 262K context decode speed, nor a guaranteed speed for arbitrary prompts; it represents a distinct workload from the fixed 2K/25K benchmarks (25.8 / 23.2 tok/s) with different input lengths, output contents, and draft acceptance rates.

## 2. Base Sources, Hardware, Model, and Execution Paths

### 2.1 Two Source Trees and Patch Structure

The build for this project combines two independent Git source trees ([config/inference-strata-gyro.env](../orin/config/inference-strata-gyro.env), [evidence/strata-gyro-orin-20261007/source-verification.json](../orin/evidence/strata-gyro-orin-20261007/source-verification.json), [Orin build helper](../orin/tools/build.sh)). The GGML backend selected for this build is the specific revision of `agentionai/llama.cpp` listed below. This is distinct from model experiments conducted separately using `llamAmpere`.

| Category | Base Repository & Upstream Commit | Ported/Pinned Revision | Role and Key Patches |
|---|---|---|---|
| **Strata Engine** (`$RUNTIME/src/strata`) | `agentionai/Strata` rc1 (`434e136f73a7da2bfd11cde3bb0aa0acaf1328c6`) + `shi3z/Strata-DGX-Spark` ARM64 changes (`324b0ef56c84f2d92e9f956354bfe38e031776fa`) | `bb98d09538fd4188feb806443da21870903057f9` (`bb98d09`) | Runtime, KV/checkpoint/conversation cache, prefill orchestration, native `TQ2_T` decode kernel, QSA/GDN/HC kernels. Initial port is [patches/strata-orin-arm64.patch](../orin/patches/strata-orin-arm64.patch), final cumulative optimization is [patches/strata-orin-sub8-f16cache.patch](../orin/patches/strata-orin-sub8-f16cache.patch) |
| **GGML Backend** (`$RUNTIME/src/agention-llama`) | `agentionai/llama.cpp` (`93a24e52cc12687213c0432af41c7fe2ab1a0eda`) | `93a24e52cc12687213c0432af41c7fe2ab1a0eda` (`93a24e5`) | Linked via `-DSTRATA_GGML_DIR`; provides routing expert matrix multiplication (`mul_mat_q`, MMQ) during prefill. - **Initial Porting Modifications** ([evidence/strata-gyro-orin-20261007](../orin/evidence/strata-gyro-orin-20261007/README.md)): When porting ARM64 changes from `Strata-DGX-Spark` and resolving CMake conflicts, Gyro's portable Hadamard implementation was preserved for both ARM64 and x86. Erroneously included HIP-specific options were removed from the CUDA build, and a failure caused by attempting to open the root-owned GPU lock file for writing was fixed by switching to a read-only file descriptor `flock`. Some log strings in upstream code (`AVX-2`, `Q5_K`) are hardcoded and do not accurately reflect the actual ARM64 fallback and `Q8_0` heads; therefore, `strata-device` selftest and `load-check` results serve as the ground truth.
- **Experimental Worktree Builds and Cumulative Patch Caveats** ([Orin build helper](../orin/tools/build.sh)): All kernel and runtime experiments left the original `$RUNTIME/src/strata` (`bb98d09`) and `$RUNTIME/build-sm87` untouched, creating isolated Git worktrees in `$RUNTIME/src-exp/<name>` where a single patch was applied and built into `$RUNTIME/build-sm87-<name>`. Consequently, files in the `patches/strata-orin-sub8-*.patch` family are each **cumulative diffs** against `bb98d09`. Applying similarly named patches in sequence will lead to conflicts; when reproducing, apply exactly one cumulative Strata patch for the target stage and one GGML fork patch ([patches/agention-llama-tq-mmq-shared-lut.patch](../orin/patches/agention-llama-tq-mmq-shared-lut.patch)).

### 2.2 Hardware, Model Configuration, and Full Expert Resident Path

- **Hardware and Compilation** ([evidence/strata-gyro-orin-20261007](../orin/evidence/strata-gyro-orin-20261007/README.md)): Jetson AGX Orin 64GB (CPU/GPU unified memory available ~61.4 GiB, theoretical peak DRAM bandwidth ~204 GB/s), GPU architecture SM87 (16 SMs, observed clock during experiments 1,300.5 MHz, power mode `MAXN` mode 0), CUDA driver/runtime 13020. CMake options used are `-DSTRATA_ENABLE_CUDA=ON -DSTRATA_BUILD_TESTS=ON -DSTRATA_PREFILL_MMQ=OFF -DCMAKE_CUDA_ARCHITECTURES=87` ([Orin build helper](../orin/tools/build.sh)).
- **NVMe Timeout Mitigation** ([evidence/strata-gyro-prefill-chunk-own-20261007-v2](../orin/evidence/strata-gyro-prefill-chunk-own-20261007-v2/README.md)): During initial engine loads, NVMe completion delays and startup times of 1,349–1,460 seconds were observed. After disabling APST and adjusting `queue/io_timeout` from 30 to 2 seconds, subsequent loads recorded 62–96 seconds. However, because configuration, page cache, and thermal history varied concurrently, this difference cannot be conclusively attributed to APST or any single factor. The polling completion timeouts cited in subsequent experiments occurred during engine loading and were not observed during measured request intervals ([evidence/strata-gyro-decode-tune-20261007-v1](../orin/evidence/strata-gyro-decode-tune-20261007-v1/README.md), [evidence/strata-gyro-sub8-ab-20261008-v1](../orin/evidence/strata-gyro-sub8-ab-20261008-v1/README.md)).
- **Model and Runtime Configuration** ([evidence/strata-gyro-orin-20261007](../orin/evidence/strata-gyro-orin-20261007/README.md), [config/inference-strata-gyro.env](../orin/config/inference-strata-gyro.env)):
  - **Initial Optimization Model**: `agentionai/Qwen3.8-Flash-Next-Gyro-GGUF` snapshot `e40c350d6a8974dc1b70cd46ec451a6e63561cb6`, file `Qwen3.8-Flash-Next-Gyro-M-TQ2_0.gguf` (SHA256 `5edfedf7398e18cb9d7cc32f40035acfc5f66bb9051e8216a053ac72d5324ee9`).
  - **Native `TQ2_T` Routed Experts and 100% GPU Cache Residency**: 48 layers in total, 24,576 experts (512 per layer, 10 activated per token, APR/Hadamard pack type 144), weight size 29.88 GiB. By specifying `--mmap-experts` alongside `--expert-cache 24576`, all 24,576 expert slots reside in the GPU cache without creating a duplicate full-expert arena in host memory (`arena_mib 0`) (100% VRAM resident zero-doorbell graph).
  - **Dense Pack and PLE**: 303 native tensors, `Q8_0` token embeddings and output head, 320,001,536 rows of PLE direct I/O (`--ple-gguf`). The compatibly converted `dense.bin` is 1,485,688,320 bytes (460 tensors: 96 exact, 364 rounded, maximum absolute error 0.0144).
  - **INT8 KV and Hybrid Layers**: INT8 KV cache configured via `--kv int8`, combining QSA attention (`prompt_attn_i8`), GDN (Gated DeltaNet) recurrent layers, and Hyper-connections (`gr_up_multi`, `gr_down_staged`).
  - **MTP Drafter**: Only the required 31 tensors (5,214,301,696 bytes) were downloaded from original `Qwen/Qwen3.8-Flash-Next` revision `de4b8e4d43b917e7706784d8bb445c9af86a3540`, verified against SHA256 hashes, and packed into runtime artifacts (`experts.bin` 707,788,800 bytes, `dense.bin` 116,099,072 bytes, default draft vocabulary 106,299 tokens) using `mtp_pack.py` (Q2_0 recipe) and `mtp_rt.py`. Actual memory footprint loaded: 813 MiB for draft layers and 275.7 MiB for the default draft head.

## 3. Measurement Methodology, Metric Definitions, and Profiling Limitations

### 3.1 Distinction Among the Four Measurement Protocols

1. **Initial Single-Run Smoke (2026-10-07, 16K Context)** ([evidence/strata-gyro-orin-20261007](../orin/evidence/strata-gyro-orin-20261007/README.md)): A functional check running one pass each of Korean conversation (28 in / 22 out), code (31 in / 128 out cap), and Korean explanation (38 in / 128 out cap). Because the original native pack required `--spec >= 2` and `--serve` strictly required MTP, MTP-disabled was run via CLI (`--spec 4 --mtp-max-t 1`) while MTP-enabled was run via the resident `--serve` runner (`--spec 4 --spec-min-p 0.5 --suffix-draft 0`). Since execution paths and timer boundaries differ, these are not used for formal speedup calculations (an instance where the native exit code remained `null` after deleting the subprocess reference before querying in the first test harness was preserved as-is rather than replaced with a success).
2. **Fixed-Input Resident A/B Benchmark (2026-10-07, 32K Context)** ([evidence/strata-gyro-mtp-20261007-v1](../orin/evidence/strata-gyro-mtp-20261007-v1/README.md), [scripts/strata-gyro-benchmark.py](../orin/tools/strata-gyro-benchmark.py)): Two Korean explanatory prompts of exactly 2,048 tokens and 25,000 tokens evaluated on the same resident `--serve` engine (the 25K input serves as a length proxy mimicking previous audit sizes, not a replay of real tools, personas, or serialization). To prevent premature termination by natural EOS, an unreachable positive EOS ID (2,147,483,647) was passed to generate exactly 512 greedy tokens. Results represent the arithmetic mean of 3 measured runs following 1 warmup run per length, with prefix, conversation, and suffix cache reuse all at zero.
3. **A-B-B-A Cross-Engine-Load Validation (2026-10-07–08, 32K Context)** ([evidence/strata-gyro-prefill-borrow-20261007-v1](../orin/evidence/strata-gyro-prefill-borrow-20261007-v1/README.md), [evidence/strata-gyro-tq2t-stage-lut-ab-20261007-v1](../orin/evidence/strata-gyro-tq2t-stage-lut-ab-20261007-v1/README.md)): A variation of approximately 0.3–0.4% in decode speed was observed across fresh engine process launches even with the identical binary. To isolate this effect, kernel change validations alternated engine loads in an a1 → b1 → b2 → a2 sequence. Similarly, short-prompt latency experiments in agent replay evaluated requests 1–12 in an on → off → on → off alternating sequence ([evidence/strata-gyro-group-gather-20261008-v1](../orin/evidence/strata-gyro-group-gather-20261008-v1/README.md), [evidence/strata-gyro-dense-f16-cache-20261009-v1](../orin/evidence/strata-gyro-dense-f16-cache-20261009-v1/README.md)).
4. **61-Request Hermes Agent Replay (2026-10-08–09, 64K Context)** ([evidence/hermes-replay-ab-20261008-v1](../orin/evidence/hermes-replay-ab-20261008-v1/README.md), [scripts/replay-strata-requests.py](../orin/tools/replay-strata-requests.py), [scripts/compare-strata-replays.py](../orin/tools/compare-strata-replays.py)): Sixty-one real Hermes agent POST requests (58 agent calls + 3 auxiliary requests) captured with [scripts/strata-request-recorder.py](../orin/tools/strata-request-recorder.py) were sequentially replayed at temperature 0 without streaming, with 65,536 context, prompt checkpoints (default 6, including root checkpoints for system prompts >= 2,048 tokens), and conversation caching (`--conversation-cache-mib 4096 --conversation-cache-slots 4`) enabled.
   - **Output Comparison Scope**: Compares response body and tool calls while excluding random tool-call `id`s generated per response. This reflects equivalence across these 61 specific requests, not byte-level HTTP equivalence or general quality validation ([comparison code](../orin/tools/compare-strata-replays.py)).
   - **Traffic Representativeness and Limitations**: During capture, the `--in DIR` argument was not forwarded to file tools, leading the agent to interpret the working directory as the home directory. Consequently, among the three tasks, only `t1` (writing `stats.py` and tests, 14 calls) produced actual code (terminal tools were absent, so `pytest` execution was omitted), whereas `t2` (bug-fixing `inventory.py`, 30 calls) and `t3` (aggregating `results.csv` with a Korean summary, 14 calls) repeatedly executed file searches (`search_files`, `read_file`) before aborting to inquire about paths. Thus, while this dataset comprises genuine agent traffic containing system prompts, tool schemas, tool execution outputs, and code generation, it is **not a completed coding task benchmark or an evaluation of general coding quality**.

### 3.2 Performance Metric Definitions (Do Not Conflate)

- **Internal Prompt Time and Internal Prefill tok/s** ([evidence/strata-gyro-mtp-20261007-v1](../orin/evidence/strata-gyro-mtp-20261007-v1/README.md)): Internal prompt time (`prompt_seconds`) encompasses sequence reset, target and draft prefill, and refilling borrowed expert slots. Because the final input token is processed by the first verify window, internal prefill throughput is calculated as (N − 1) / prompt_seconds. The `PP` timer in engine logs is a per-chunk cumulative value that excludes the final refill interval.
- **IPC TTFT (Time To First Token)**: The duration from client request dispatch until arrival of the first generated token. This is not pure prefill time; it includes computation for the initial verify window and IPC stream latency.
- **Decode tok/s (Internal vs Stream vs Replay Aggregate)**:
  - In the fixed 512-token benchmark, internal decode throughput is 512 / internal_decode_seconds, while the primary comparison metric in the table, **IPC stream decode throughput**, is computed using the arrival timestamp difference between the first and last token as (512 − 1) / (last − first) ([evidence/strata-gyro-mtp-20261007-v1](../orin/evidence/strata-gyro-mtp-20261007-v1/README.md)).
  - The **aggregate decode throughput** of the 61-request replay is the total number of generated tokens across all 61 requests (21,644 tokens) divided by the sum of server-reported decode times. Converting milliseconds to seconds, the formula is 1,000 × Σ predicted_n / Σ predicted_ms with units of tok/s ([evidence/hermes-replay-ab-20261008-v1](../orin/evidence/hermes-replay-ab-20261008-v1/README.md)).
- **IPC Total s and Replay Wall s**: The total elapsed duration from the start of a single request until receipt of `DONE` (`IPC total s`), or the sum of per-request HTTP elapsed times recorded as `wall_seconds` during replay (`Wall s`). The latter does not represent the end-to-end execution time of the entire script process including preparation and result serialization ([aggregation code](../orin/tools/compare-strata-replays.py)).

### 3.3 Profiling and Telemetry Interpretation Limitations

- **Nsight Systems (`nsys`) Overhead** ([evidence/strata-gyro-profile-20261007-v1](../orin/evidence/strata-gyro-profile-20261007-v1/README.md), [evidence/strata-gyro-profile-sub8-graph-20261008-v1](../orin/evidence/strata-gyro-profile-sub8-graph-20261008-v1/README.md)): Tracing CUDA graphs on an individual node basis (`--cuda-graph-trace=node`) degrades decode throughput by ~19% (21.3 → 17.26 tok/s) and prefill throughput by ~1% (528.9 → 524.5 tok/s). Node-level tracing is reserved exclusively for extracting relative time breakdowns by kernel name; host gaps and graph runtimes are measured using graph-level tracing (`--cuda-graph-trace=graph`, overhead ~1.5–1.9%).
- **Nsight Compute (`ncu`) OOM and Standalone Harness Limitations** ([evidence/strata-gyro-ncu-20261007-v1](../orin/evidence/strata-gyro-ncu-20261007-v1/README.md), [evidence/strata-gyro-kernel-tq2t-20261007](../orin/evidence/strata-gyro-kernel-tq2t-20261007/README.md), [evidence/strata-gyro-tq2t-stage-lut-ab-20261007-v1](../orin/evidence/strata-gyro-tq2t-stage-lut-ab-20261007-v1/README.md)): Attaching `ncu --graph-profiling node` to an engine loaded with the 30 GiB expert cache caused kernel replay to balloon anonymous RSS to 61.5 GB, triggering an NvMap allocation failure (`error 12`) and the kernel OOM killer. To circumvent this, rather than using the default single-expert call mode, `native_expert_parity` was augmented with a mode simulating the actual decode grid (e.g., `STRATA_BENCH_GROUPED=1:30`, 10 experts × T tokens, rotating across 64 weight copies) with GPU devfreq pinned to 1,300.5 MHz for profiling. The 17 GB/s figure observed in the initial single-group parity harness reflected weights decoded repeatedly out of cache and must not be interpreted as actual engine memory bandwidth.
- **ASTOP and Board Telemetry** ([evidence/strata-gyro-mtp-20261007-v1](../orin/evidence/strata-gyro-mtp-20261007-v1/README.md), [evidence/strata-gyro-prefill-borrow-20261007-v1](../orin/evidence/strata-gyro-prefill-borrow-20261007-v1/README.md)): On this board's ASTOP backend, GPU power and per-process GPU memory/utilization are unsupported and recorded as `null`; these are not converted to 0. In `tegrastats`, `VDD_GPU_SOC` represents board rail power with aggregated SoC load. Furthermore, occurrences where ASTOP records PID monitoring terminations as `disappeared` (termination status `unknown`) due to platform characteristics are not taken as evidence of success; task completion is established strictly through wrapper exit code (0), native engine exit code (0), `systemd` status (`ExecMainStatus=0`), and result file validation.

## 4. Step-by-Step Optimization Progression

### 4.1 Establishing MTP Speculative Decoding Baseline (2026-10-07)

- **Bottleneck**: Decoding the target model alone required executing 48 layers of routed experts and dense projections for every output token, yielding ~14.5–14.6 tok/s on these benchmark prompts ([evidence/strata-gyro-mtp-20261007-v1](../orin/evidence/strata-gyro-mtp-20261007-v1/README.md)).
- **Modification**: Using the identical resident engine binary (`8ce7f7cb…5354`), weights, 32K context, INT8 KV, and 1,024 prefill chunks, MTP-disabled (`--mtp-max-t 1`, draft graph bypassed) and MTP-enabled (`--spec 4 --spec-min-p 0.5`) were evaluated head-to-head ([config/strata-gyro-mtp-benchmark-v1.json](../orin/config/strata-gyro-mtp-benchmark-v1.json)).
- **Measurement**: On the 2,048-token input, stream decode improved from 14.60 → **20.35 tok/s** (1.394×, total time 43.839 → 33.867 s); on the 25,000-token input, it increased from 14.51 → **19.93 tok/s** (1.374×, total time 155.622 → 145.322 s). Draft acceptance rates were 70.56% (290/411) for 2K and 73.51% (283/385) for 25K, with 100% token-for-token agreement across all 512 generated tokens between both conditions and across 3 repetitions. Conversely, internal prefill speed on 25K was 207.81 vs 209.03 tok/s (TTFT ~120 s), differing by under 1% ([evidence/strata-gyro-mtp-20261007-v1](../orin/evidence/strata-gyro-mtp-20261007-v1/README.md)).
- **Adoption Rationale**: Adopted as the default decode path for all subsequent experiments because it increased decode speed by ~1.37–1.39× without altering outputs.

### 4.2 Dedicated Prefill Buffer (`--no-prefill-borrow`) and Chunk Size Expansion (`--prefill 8192`) (2026-10-07)

- **Bottleneck (Borrowed-Slot Streaming)**: Re-analyzing 25K prefill telemetry from the MTP baseline revealed that GPU activity (GR3D) dropped below 50% in 20–29% of 1-second `tegrastats` samples (~1 idle period per 1,024-token chunk), while single CPU core utilization spiked to 85.7% (peaking near 100%). Simultaneously, the engine's mapped GGUF copy counter (`file_read_bytes_`, `src/core/expert_source.cpp`) incremented by 17,693.5 MB per 25K request (~690 MB per chunk, matching the 0.64 GiB footprint of 528 borrowed slots) and by 1,835.7 MB per 2K request. This occurred because default settings borrowed GPU expert cache slots to acquire working buffer space for prefill (`borrow`), streamed experts from mapped GGUF via host copies during prefill, and refilled them at the end (Note: this counter reflects logical bytes copied from mapped GGUF, not actual physical NVMe read volume) ([evidence/strata-gyro-prefill-borrow-20261007-v1](../orin/evidence/strata-gyro-prefill-borrow-20261007-v1/README.md)).
- **Modification 1 (`--no-prefill-borrow`)**: With ~20,798 MiB of free memory remaining post-load, `--no-prefill-borrow` was added to allocate an isolated dedicated prefill buffer (589 MiB reserved, free memory 20,798 → 20,209 MiB) while maintaining chunk size at 1,024 for comparison ([config/strata-gyro-prefill-borrow-v1.json](../orin/config/strata-gyro-prefill-borrow-v1.json)).
- **Measurement 1**: In-place GGUF copying per request dropped to **0.0 MB**; during 25K prefill, average GR3D rose from 73.2% → 98.7% (samples below 50% dropped to 0.0%), and busiest CPU core utilization fell from 85.7% → 4.5%. Internal prefill throughput increased from 235.19 → **286.57 tok/s** at 2K (TTFT 8.774 → 7.212 s, 1.216×) and from 208.44 → **280.81 tok/s** at 25K (TTFT 120.033 → 89.111 s, 30.9 s reduction, 1.347×), with outputs matching token-for-token ([evidence/strata-gyro-prefill-borrow-20261007-v1](../orin/evidence/strata-gyro-prefill-borrow-20261007-v1/README.md)).
- **Modification 2 (`--prefill 8192` Chunk Sweep)**: With prefill now operating at 98.7% GPU compute on the dedicated buffer, `--prefill` chunk sizes were swept across 1,024 / 2,048 / 4,096 / 8,192 (free memory post-load at 32K context: 20,174 / 19,819 / 18,965 / 17,123 MiB) ([evidence/strata-gyro-prefill-chunk-own-20261007-v2](../orin/evidence/strata-gyro-prefill-chunk-own-20261007-v2/README.md), [config/strata-gyro-prefill-chunk-own-v1.json](../orin/config/strata-gyro-prefill-chunk-own-v1.json)).
- **Measurement 2 and Output Divergence Caveat**: The 2,048 input fit into a single chunk at chunk sizes >= 2,048, raising prefill speed from 287.21 → 396.38–399.31 tok/s (TTFT 7.196 → 5.196–5.233 s). On the 25,000 input, prefill scaled from 281.45 (c1024) → 381.60 (c2048) → 475.14 (c4096) → **528.87 tok/s (c8192)**, reducing 25K TTFT from 88.916 s → **47.350 s** (1.879× faster than owned c1024, 2.54× faster than initial borrowed c1024). However, altering chunk size changed the greedy output tokens compared to c1024 (diverging at token 113 for 2K, and at token 33 for 25K c8192). Although weights, KV format, and kernel implementations remained identical with only prefill batching altered, differences in accumulation/reduction order or tile dispatch across chunk boundaries and matrix dimensions can affect MoE routing and QSA selection, and boundary-handling bugs cannot be definitively ruled out; therefore, this divergence is not assumed to be harmless rounding without evidence, nor is any claim of semantic superiority asserted ([evidence/strata-gyro-prefill-chunk-own-20261007-v2](../orin/evidence/strata-gyro-prefill-chunk-own-20261007-v2/README.md)).
- **Adoption Rationale**: Adopted `--no-prefill-borrow --prefill 8192` as the baseline configuration for all subsequent experiments and serving based on the decisive reduction in long-input TTFT from 120 s to 47.35 s.

### 4.3 `TQ2_T` Routed-Expert Decode Kernel Pass 1: Shared-Memory Row and Codebook Staging (`stage-lut`) (2026-10-07)

- **Bottleneck**: In Nsight Systems profiling ([evidence/strata-gyro-profile-20261007-v1](../orin/evidence/strata-gyro-profile-20261007-v1/README.md)), `TQ2_T` routed-expert kernels (`native_gu_multi_kernel<144>`, `native_down_multi_kernel<144>`) accounted for 37.8% (4.996 s) of decode GPU time (dense `Q8_0` MMVQ 32.6%, Hyper-connection 14.1%, MTP draft head 4.3%, attention 3.9%, GDN 3.6%). In standalone profiling of the decode geometry (`STRATA_BENCH_GROUPED=1:30`, T = 1, 1,600 blocks), the gate/up kernel was bound not by DRAM, but by **L1/TEX cache bandwidth (70% of peak; L2 was at 17%)**. Because every lane performed random lookups into the 4 KB int8 trellis codebook (`tq_lut_i8`) in global memory, each warp global load hit ~21 L1 sectors (972,800 requests, 20.6M sectors), with stalls driven 22% by long scoreboard, 20% by LG throttle, and 19% by MIO throttle ([evidence/strata-gyro-tq2t-stage-lut-ab-20261007-v1](../orin/evidence/strata-gyro-tq2t-stage-lut-ab-20261007-v1/README.md)).
- **Modification**: Via [patches/strata-orin-tq2t-stage-lut.patch](../orin/patches/strata-orin-tq2t-stage-lut.patch) (binary `strata.tq2t-stage-lut`, SHA256 `1d62562c…`), (1) each warp used 4-byte `cp.async` to copy its entire `TQ2_T` weight row into a per-warp shared memory buffer before executing the existing lane loop ([patches/strata-orin-tq2t-stage.patch](../orin/patches/strata-orin-tq2t-stage.patch), [evidence/strata-gyro-kernel-tq2t-20261007](../orin/evidence/strata-gyro-kernel-tq2t-20261007/README.md)), and (2) grouped gate/up and down kernels staged the 4 KB codebook (`tq_lut_i8`) into block shared memory for lookups. Decode values and summation order remained unchanged.
- **Measurement**: In standalone grouped benchmarks locked at 1.30 GHz, per-invocation runtime (gate/up + SwiGLU/quantize + down) at T = 1/2/4 dropped from baseline 440.2 / 857.6 / 1,691 µs → row staging 412.0 / 801.7 / 1,582 µs → **row + codebook staging 353.0 / 684.7 / 1,348 µs** (−19.8% at T = 1); `native_expert_parity` for layers 10 and 30 matched baseline error statistics, with bitwise equivalence verified across width invariance and decode-once/per-entry comparisons. In engine A-B-B-A benchmarks ([config/strata-gyro-tq2t-stage-lut-ab-v1.json](../orin/config/strata-gyro-tq2t-stage-lut-ab-v1.json)), stream decode throughput rose from 21.28 → **22.97–23.00 tok/s** (+7.9 to +8.1%) on 2K input and from 19.24 → **20.72–20.76 tok/s** (+7.7 to +7.9%) on 25K input, with per-window verify time dropping from 101.7 → 93.3 ms (2K, −8.3%). Outputs across all 32 requests matched the baseline token-for-token ([evidence/strata-gyro-tq2t-stage-lut-ab-20261007-v1](../orin/evidence/strata-gyro-tq2t-stage-lut-ab-20261007-v1/README.md)).
- **Adoption Rationale**: Adopted because it yielded an ~8% decode throughput improvement while maintaining output identity across the verified kernel paths and both benchmark prompts.

### 4.4 GGML Fork MMQ Kernel's Shared-Memory Codebook (`mmq-lut`) (2026-10-07)

- **Bottleneck**: In the GGML fork's `mul_mat_q` (MMQ) kernel, which accounted for 39.9% of GPU time during 25K prefill ([evidence/strata-gyro-profile-20261007-v1](../orin/evidence/strata-gyro-profile-20261007-v1/README.md)), the tile loader's `tq_lane_to_q8` was likewise reading `tq_lut_i8` from global memory.
- **Modification**: Applied [patches/agention-llama-tq-mmq-shared-lut.patch](../orin/patches/agention-llama-tq-mmq-shared-lut.patch) to `agentionai/llama.cpp` (`93a24e5`) (binary `strata.mmq-lut`, SHA256 `e4566270…`), populating the shared-memory copy `tq_lut_i8_s` (previously used by mat-vec kernels) at the start of `mul_mat_q` for trellis types and directing `tq_lane_to_q8` to read from it ([evidence/strata-gyro-mmq-lut-ab-20261007-v1](../orin/evidence/strata-gyro-mmq-lut-ab-20261007-v1/README.md)).
- **Measurement**: In A-B-B-A prefill benchmarks ([config/strata-gyro-mmq-lut-ab-v1.json](../orin/config/strata-gyro-mmq-lut-ab-v1.json)), internal prefill throughput rose from 397.61–398.48 → **419.88–420.95 tok/s** (+5.6 to +5.9%, TTFT 5.21 → 4.93 s) on 2K input and from 529.07–530.41 → **554.91–555.34 tok/s** (+4.9 to +5.0%, TTFT 47.34 → 45.10 s) on 25K input. Because MMQ decodes weight tiles once and reuses them across multiple token columns, the relative gain was smaller than in decode kernels; however, decode throughput was fully preserved and outputs across all 32 requests were identical ([evidence/strata-gyro-mmq-lut-ab-20261007-v1](../orin/evidence/strata-gyro-mmq-lut-ab-20261007-v1/README.md)).
- **Adoption Rationale**: Adopted as the default GGML patch for all subsequent builds as it reduced prefill time by ~5% without numerical divergence.

### 4.5 `TQ2_T` Routed-Expert Decode Kernel Pass 2: 4 Rows per Warp and Sub-Warp Down (`rpw4/sub8`) (2026-10-08)

- **Bottleneck**: Even after the first kernel optimization pass, the gate/up kernel re-read `q8_1` activations row-by-row in single-entry groups, while in the down kernel (K = 40 blocks, `n_ff` = 640), the 32-lane warp loop underutilized hardware by having only 8 active lanes on its second pass ([evidence/strata-gyro-sub8-ab-20261008-v1](../orin/evidence/strata-gyro-sub8-ab-20261008-v1/README.md)).
- **Modification**: In [patches/strata-orin-tq2t-rpw4-sub8.patch](../orin/patches/strata-orin-tq2t-rpw4-sub8.patch) (binary `strata.sub8`, SHA256 `2690172711be…`), (1) gate/up was structured so each warp processed 4 rows (32 rows per block), reading `q8_1` activations once per lane step for reuse across 4 rows (`rpw4`), and (2) for down rows with K = 40, the existing 8-lane sub-warp path (`row_dot_40_sub8`) was activated in conjunction with the shared-memory codebook (`sub8`). The reduction tree and summation sequence remained unchanged.
- **Measurement**: In standalone grouped benchmarks locked at 1.30 GHz ([scripts/bench-strata-gyro-grouped.sh](../orin/tools/bench-strata-gyro-grouped.sh)), T = 1/2/4 invocation times dropped from `mmq-lut` 352.6 / 684.8 / 1,348 µs → `rpw4` alone 329.1 / 628.7 / 1,233 µs → **`sub8` combined 247.2 / 464.6 / 902.6 µs** (−29.9% at T = 1). Parity error statistics for layers 10 and 30 matched the baseline, passing both decode-once/per-entry and width invariance checks. In engine A-B-B-A benchmarks ([config/strata-gyro-sub8-ab-v1.json](../orin/config/strata-gyro-sub8-ab-v1.json)), stream decode throughput improved from 22.94–22.95 → **25.73–25.80 tok/s** (+12.1 to +12.5%, total time 27.20 → 24.77 s) on 2K input and from 20.71 → **23.13–23.20 tok/s** (+11.7 to +12.0%, total time 69.80 → 67.14 s) on 25K input, with per-window verify time reduced from 93.5 → 82.2 ms (2K). Output tokens across all 32 requests were identical ([evidence/strata-gyro-sub8-ab-20261008-v1](../orin/evidence/strata-gyro-sub8-ab-20261008-v1/README.md)).
- **Adoption Rationale**: Adopted based on an ~12% decode gain in this stage's A-B-B-A evaluation and confirmed output token identity across both prompts. Overall progression relative to prior stages is distinguished as a separate experimental record in Section 6.1.

### 4.6 Reducing Multi-Turn Prompt Fixed Costs: Coalesced Dequantization and Consecutive-Turn Parking Bypass (`dqpark`) (2026-10-08)

- **Bottleneck**: Analysis of real Hermes multi-turn tasks ([evidence/hermes-strata-orin-20261008](../orin/evidence/hermes-strata-orin-20261008/README.md)) and the 61-request replay ([evidence/hermes-replay-ab-20261008-v1](../orin/evidence/hermes-replay-ab-20261008-v1/README.md)) revealed that despite prefix caching limiting newly read tokens to 64–511 tokens per turn (across 32 requests), a fixed prompt overhead of ~1.5–1.9 seconds occurred on every turn, causing prompt processing to consume 271.9 s (~24.5%) of total wall time (1,110.0 s). Instrumenting via [patches/strata-orin-sub8-ptime.patch](../orin/patches/strata-orin-sub8-ptime.patch) (`STRATA_PROMPT_TIMING=1`) and Nsight Systems (requests 4–5, 99 and 153 tokens read) isolated two causes ([evidence/strata-gyro-prompt-fixed-cost-20261008-v1](../orin/evidence/strata-gyro-prompt-fixed-cost-20261008-v1/README.md)):
  1. The generic `dequant_kernel` dequantizing dense `Q8_0` weights to FP16 prior to cuBLAS calls assigned 32 values per thread, writing scalar half-precision values across adjacent threads with a 64-byte stride (uncoalesced), consuming 937 ms across 602 launches on those two short reads alone.
  2. Hermes re-renders and retransmits prior assistant responses on each turn, resuming from the preceding turn boundary checkpoint rather than a live session; the engine was parking the prior live session into conversation cache (`park`, averaging 0.38 s/turn, totaling 23.0–25.8 s) only to evict it as a superseded copy during the next park operation.
- **Modification**:
  1. **Coalesced Dequant** ([patches/strata-orin-sub8-dqpairs.patch](../orin/patches/strata-orin-sub8-dqpairs.patch)): Introduced `dequant_q8_0_f16_pairs`, assigning 2 values (1 pair) per thread so warps write contiguous 128-byte segments (verified bit-identical to FP32 multiplication followed by rounding via `dequant_bf16_test`).
  2. **Consecutive-Turn Parking Bypass** ([patches/strata-orin-sub8-dqpark.patch](../orin/patches/strata-orin-sub8-dqpark.patch), binary `strata.dqpark`, SHA256 `53c28eed…`): Modified the engine to skip parking the outgoing session when a request resumes from the **deepest checkpoint** of the live chain (parking remains active when resuming from other points, such as auxiliary requests sharing only the system prompt root).
- **Measurement**: Coalesced dequantization cut runtime across 602 launches from 937 → 221 ms, reducing fixed fitting overhead for short reads (<2,048 tokens) from 1,160 → 812 ms (sum of prompt times across 61 requests dropped from 266.0 → 247.8 s). Adding the parking bypass eliminated unnecessary parking across 53 turns (parking duration 25.8 → 2.1 s, preserving 3 genuine conversation cache restores), bringing total prompt time to **222.9 s** and total wall time to **1,056.3 s** (−4.1% vs timing build 1,101.6 s), with outputs across all 61 requests identical ([evidence/strata-gyro-prompt-fixed-cost-20261008-v1](../orin/evidence/strata-gyro-prompt-fixed-cost-20261008-v1/README.md)).
- **Adoption Rationale**: Adopted because it reduced the prompt sum by 43.1 s relative to `ptime` in this replay with identical outputs across all 61 requests. This does not imply identical per-request savings or equivalent results across arbitrary agent workloads.

### 4.7 Checkpoint Buffer Recycling (`recycle`) and `enko` Draft Vocabulary Reduction (2026-10-08)

- **Bottleneck 1 (Checkpoint Allocation Overhead)**: Saving turn-boundary checkpoints allocated fresh pageable vectors of ~118 MB each time, incurring page faults and zero-fill overhead that consumed ~100 ms per turn (totaling 5.8–6.1 s across 61 requests) ([evidence/strata-gyro-prompt-fixed-cost-20261008-v1](../orin/evidence/strata-gyro-prompt-fixed-cost-20261008-v1/README.md), [evidence/strata-gyro-agent-round2-20261008-v1](../orin/evidence/strata-gyro-agent-round2-20261008-v1/README.md)).
- **Modification 1 and Measurement (`recycle`)**: In [patches/strata-orin-sub8-recycle.patch](../orin/patches/strata-orin-sub8-recycle.patch) (binary `strata.recycle`, SHA256 `4ea3f309…`), buffers from checkpoints evicted by LRU were retained and reused for subsequent saves rather than freed. Total checkpoint saving duration across 61 requests dropped from 5.8 → **2.6 s** (~50 ms saved per turn), total prompt time fell from 222.9 → **219.9 s**, and all 61 outputs remained identical ([evidence/strata-gyro-agent-round2-20261008-v1](../orin/evidence/strata-gyro-agent-round2-20261008-v1/README.md)).
- **Bottleneck 2 (Draft Head Dimensions)**: The default MTP draft vocabulary (`rt/draft_vocab.bin`) contained 106,299 tokens (275.7 MiB of head rows)—including 55,328 Han tokens and 5,476 kana tokens—reading all weights on every draft step and consuming 13.13 ms of draft time per window ([evidence/strata-gyro-agent-round2-20261008-v1](../orin/evidence/strata-gyro-agent-round2-20261008-v1/README.md)).
- **Modification 2 and Measurement (`enko`)**: Using `tools/draft_vocab.py`, the base English and code subset (`data/draft_vocab_en.bin`, 40,525 tokens) was augmented with all Hangul and CJK punctuation tokens to generate `mtp/rt-enko` ([config/strata-gyro-replay-enko.json](../orin/config/strata-gyro-replay-enko.json)) totaling **47,493 tokens (123.2 MiB)**. Across the 61-request replay (weighted average over 8,034 windows), per-window draft time dropped from 13.13 → **9.98 ms** (−3.15 ms), while accepted drafts held constant at 13,681 (no loss in acceptance rate on the Korean summary task `t3`). Aggregate decode speed rose from 26.19 → **27.09 tok/s** (+3.4%), total wall time dropped from 1,057.8 → **1,030.6 s**, and outputs across all 61 requests were 100% identical ([evidence/strata-gyro-agent-round2-20261008-v1](../orin/evidence/strata-gyro-agent-round2-20261008-v1/README.md)).
- **Adoption Rationale and Language Constraint Caveat**: In an architecture where the target model verifies candidate tokens, this was adopted because the 61 checked replay outputs remained identical and aggregate decode accelerated by 3.4%. These results reflect this specific traffic and do not guarantee generalized cross-lingual performance or output identity on arbitrary inputs. Crucially, because tokens outside the subset (retaining only 36 Han tokens and 85 kana tokens) cannot be proposed as draft candidates, **MTP draft performance is severely constrained during Chinese and Japanese generation**. Output identity in this replay must not be extrapolated as proof of draft quality across all languages or inputs.

### 4.8 Resident Expert Single-Launch Group Gather (`grpres`) (2026-10-08)

- **Bottleneck**: For short batched reads under 1,024 tokens (non-streaming walk), `group_gather` was guarded strictly by the `stream_all` condition; even when all routed experts were GPU-resident in cache, individual `gather_native` (`copy16_kernel`) calls were launched per expert to copy into the 16-expert MMQ group buffer (taking ~200 ms per short read) ([evidence/strata-gyro-prompt-fixed-cost-20261008-v1](../orin/evidence/strata-gyro-prompt-fixed-cost-20261008-v1/README.md), [evidence/strata-gyro-group-gather-20261008-v1](../orin/evidence/strata-gyro-group-gather-20261008-v1/README.md)).
- **Modification**: In [patches/strata-orin-sub8-grpres.patch](../orin/patches/strata-orin-sub8-grpres.patch) (binary `strata.grpres`, SHA256 `084de42f…`, source commit `de173bd` + test `5d1beaa`), even during non-streaming walks, when all routed experts for a layer are resident, copies are batched into a single `gather_native_group` launch per group ([evidence/strata-gyro-group-gather-20261008-v1](../orin/evidence/strata-gyro-group-gather-20261008-v1/README.md)).
- **Measurement**: In unit testing (`mmq_gather_group_test.cpp`), copying 16 experts dropped from 295.3 → 233.7 µs (effective bandwidth 142 → 179 GB/s, saving ~20% launch/scheduling overhead) with bitwise equivalence. Alternating verification (on/off/on/off) on requests 1–12 showed 10 out of 11 non-streaming reads accelerated by 42–80 ms (sum dropped from 15.58 → 15.02 s, −3.6%), and total prompt time across the full 61-request replay fell from 219.1–220.0 s → **217.9 s** (short-read fixed cost 802 → 736 ms), with all 61 outputs identical ([evidence/strata-gyro-group-gather-20261008-v1](../orin/evidence/strata-gyro-group-gather-20261008-v1/README.md)).
- **Adoption Rationale**: Adopted because alternating measurements demonstrated a 40–80 ms reduction in short-prompt latency alongside identical outputs. Total wall-time differences remained within decode run-to-run variance and are not claimed as an established end-to-end throughput gain.

### 4.9 Dense FP16 Weight Cache for Prompts (`f16cache`) (2026-10-09)

- **Bottleneck**: Even with coalesced dequantization (`dequant_q8_0_f16_pairs`), re-dequantizing ~300 dense `Q8_0` weights into scratch buffers as FP16 on every prompt batch read consumed ~110 ms per read ([evidence/strata-gyro-prompt-fixed-cost-20261008-v1](../orin/evidence/strata-gyro-prompt-fixed-cost-20261008-v1/README.md), [evidence/strata-gyro-dense-f16-cache-20261009-v1](../orin/evidence/strata-gyro-dense-f16-cache-20261009-v1/README.md)).
- **Modification**: In [patches/strata-orin-sub8-f16cache.patch](../orin/patches/strata-orin-sub8-f16cache.patch) (binary `strata.f16cache`, SHA256 `996f228f4e3b16c61ba804589f3053b678a9401c5837159a2f2e44fefd4b3256`, source commit `9acaf8e`), `Gemm::native` (`src/prefill/gemm.cu`) retains FP16 copies of dense weights dequantized during the initial prompt read, indexed by weight address, geometry, and type; subsequent reads bypass dequantization and invoke cuBLAS GEMM directly. The cache is guarded by an upper bound `STRATA_DENSE_F16_CACHE_MIB` (default 6,144 MiB) and a free-memory floor `STRATA_DENSE_F16_CACHE_FLOOR_MIB` (default 8,192 MiB) ([evidence/strata-gyro-dense-f16-cache-20261009-v1](../orin/evidence/strata-gyro-dense-f16-cache-20261009-v1/README.md)).
  - **Preventing Misunderstanding**: This feature **caches copies of dense projection weights (`Q8_0` → FP16) that were already being dequantized into scratch memory during prefill**. It is **not an FP16 KV cache (`--kv int8` is preserved), nor does it convert the 24,576 routed experts (`TQ2_T`) to FP16**. Its primary impact is reducing prompt latency; decode throughput differences are within noise.
- **Measurement and Memory Cost**: With 16,306 MiB free memory immediately post-load, the first prompt read after server boot (4,346 tokens) populated **5,597 MiB** across ~300 weights, paying a one-time allocation cost of +120 ms (leaving 10,567 MiB free thereafter). All subsequent reads (99–1,713 tokens) achieved **reductions of 88–101 ms per read** ([compare-1-12.txt](../orin/evidence/strata-gyro-dense-f16-cache-20261009-v1/compare-1-12.txt)). Across the full 61-request replay ([compare-61.txt](../orin/evidence/strata-gyro-dense-f16-cache-20261009-v1/compare-61.txt)), total prompt time decreased from 217.9 → **211.1 s** (−6.8 s, −3.1%; short-read fixed overhead reduced from 736 → 634 ms), total wall time fell from 1,033.2 → **1,026.9 s**, and aggregate decode throughput reached **27.02 tok/s** (all 61 outputs identical) ([evidence/strata-gyro-dense-f16-cache-20261009-v1](../orin/evidence/strata-gyro-dense-f16-cache-20261009-v1/README.md)).
- **Adoption Rationale**: Adopted as the final text engine because outputs matched across alternating tests and all 61 replay requests, while batch read latency dropped by ~100 ms after the initial request.

### 6.3 Final Adopted Configuration, Memory Footprint, and Summary of Modifications vs Unchanged Components

- **Final 64K Replay Configuration** ([config/strata-gyro-replay-f16cache.json](../orin/config/strata-gyro-replay-f16cache.json)): Binary `strata.f16cache` (SHA256 `996f228f4e3b16c61ba804589f3053b678a9401c5837159a2f2e44fefd4b3256`), `--mmap-experts --expert-cache 24576 --pool-workers 2 --no-prefill-borrow --prefill 8192 --max-context 65536 --kv int8 --spec 4 --spec-min-p 0.5 --mtp $RUNTIME/mtp/rt-enko --conversation-cache-mib 4096 --conversation-cache-slots 4`.
- **Memory Footprint (Relative to 64GB Unified Memory)** ([evidence/strata-gyro-orin-20261007](../orin/evidence/strata-gyro-orin-20261007/README.md), [evidence/strata-gyro-prefill-chunk-own-20261007-v2](../orin/evidence/strata-gyro-prefill-chunk-own-20261007-v2/README.md), [evidence/strata-gyro-dense-f16-cache-20261009-v1](../orin/evidence/strata-gyro-dense-f16-cache-20261009-v1/README.md)):
  - All 24,576 routed experts in GPU cache: 29.88 GiB (`arena_mib 0`).
  - MTP draft layers 813 MiB + `enko` draft head 123.2 MiB (saving 152.5 MiB from default 275.7 MiB).
  - Dedicated prefill buffer (`--no-prefill-borrow --prefill 8192`): Free memory post-load at 32K context shifted from borrowed c1024 (20,798 MiB) → dedicated c1024 (20,209 MiB, 589 MiB reserved) → dedicated c8192 (17,123 MiB).
  - At 64K context with 16,306 MiB free post-load, the **Dense FP16 weight cache (~300 tensors) occupied 5,597 MiB** during the first prompt read, leaving 10,567 MiB free; subsequently, conversation caching utilized up to ~3.5 GB in host RAM.
- **What Changed vs What Was Kept**:
  - *What Changed*: ARM64/SM87 porting, dedicated prefill buffer and 8,192 chunking, `TQ2_T` decode kernels (`cp.async` row staging, shared-memory codebook, 4 rows per warp for gate/up, 8-lane sub-warp for down), GGML MMQ shared-memory codebook, prompt `Q8_0` → FP16 coalesced dequantization and dense FP16 weight caching, parking bypass on consecutive checkpoints, checkpoint buffer recycling, single-launch group gather for resident experts, and `enko` 47,493-token draft vocabulary.
  - *What Was Kept*: Within the October 7–9 optimization scope utilizing packs generated during the initial port, model weights, quantization formats, INT8 KV, and base MTP policy were preserved. Kernel checks and output equivalence on respective benchmark prompts and replays were verified for each adopted patch. Rounding in initial dense pack conversions, output divergence upon chunk size changes, and subsequent abliterated weight substitutions are separate from this claim.
- **Remaining Decode Cost Breakdown and Stopping Rationale** ([evidence/strata-gyro-profile-sub8-graph-20261008-v1](../orin/evidence/strata-gyro-profile-sub8-graph-20261008-v1/README.md), [evidence/strata-gyro-draft-measure-20261008-v1](../orin/evidence/strata-gyro-draft-measure-20261008-v1/README.md)): Graph-level tracing modeled verify graph duration with the linear approximation verify ≈ 44.1 ms + 13.4 ms × T; under `enko`, total time per window was ~99.5 ms (verify 89.5 ms + draft 10.0 ms, averaging 2.694 tokens/window). Reaching 30 tok/s would require reducing window latency by an additional ~10–13 ms. However, aggregating all identified medium-impact overheads—verify graph host launch gaps (~1.09 ms), GDN state commit (`gdn_step_commit_kernel`, 1.68 ms; because per-candidate state is not retained, pointer swapping is infeasible and states are recalculated for accepted tokens), and redundant draft round preparation (~0.39–0.42 ms)—yields an upper-bound potential reduction of ~3.5 ms (equivalent to +0.99 tok/s), assuming zero added cost. This is neither a realized saving nor a performance projection, nor does it serve as proof that 30 tok/s is impossible or that 27 tok/s represents a hardware ceiling.

## 7. Subsequent Deployment History and Limitations (2026-10-09 to 10-15)

The three deployment operations described below, conducted after concluding the initial performance experiments, represent operational records modifying context capacity, multimodal capabilities, and weight revisions, and are treated separately from the initial benchmarks.

1. **2026-10-09: 262K Context Verification and Persistent Deployment** ([evidence/strata-gyro-262k-persistent-20261009-v1](../orin/evidence/strata-gyro-262k-persistent-20261009-v1/README.md))
   - Retained the identical `strata.f16cache` binary (`996f228f…`), `mtp/rt-enko`, INT8 KV, 24,576 expert slots, and 8,192 prefill chunks, expanding only `--max-context 262144`.
   - Passed 11 checks—including 3/3 start/middle/end needle retrievals, tool calling, conversation turns, and SSE—on cold-prefix (`cache_n=0`) synthetic inputs of 64,000 tokens (internal prefill 112.6 s, HTTP 114.3 s, internal decode 32.4 tok/s), 128,000 tokens (prefill 233.0 s, HTTP 235.0 s, decode 31.9 tok/s), and 253,952 tokens (prefill 494.2 s, HTTP 496.7 s, decode 30.8 tok/s, leaving 8,192 tokens output headroom).

2. **2026-10-11: Abliterated Gyro-M Weights and CUDA Vision (`strata-vision`) Deployment** ([evidence/gyro-abliterated-vision-deploy-20261011-v1](../orin/evidence/gyro-abliterated-vision-deploy-20261011-v1/README.md))
